이카루스 프로젝트 ObjectPoolingSystem 사용자 설명서

1. 핵심 철학과 역할 분담 (Core Philosophy & Role Separation)
오브젝트 풀링 시스템은 3계층 아키텍처의 단일 책임 원칙에 따라 메모리 관리와 데이터 참조 역할을 완벽하게 분리하여 동작합니다.

생성과 메모리 제어: ObjectPoolManager는 객체를 Instantiate(생성)하고 Destroy(파괴/비활성화)하는 메모리 관리만 전담합니다. 인게임 객체의 생성과 파괴 자체는 전적으로 ObjectPoolManager가 통제합니다.

상태 및 참조 관리: ActorHub(또는 ObjectHub)는 직접 객체를 생성하지 않으며, 풀에서 꺼내져 씬에 활성화된 객체들의 참조(Reference) 목록만 쥐고 있는 전화번호부 역할을 수행합니다. 인게임 객체들은 그룹이나 태그(Tag)를 기반으로 식별되어 관리됩니다.



2. 프레임 최적화와 프리워밍 (Performance Optimization & Pre-warming)
게임 플레이 중 화면 멈춤(Spike) 현상을 원천 차단하기 위해 무거운 C++ 네이티브 연산을 로딩 구간으로 밀어냅니다.

로딩 씬 기반 할당: 씬이 로드될 때 플레이어 눈에는 로딩 화면만 보이므로, 이때 풀 매니저가 객체(예: 몬스터 100마리)를 Instantiate()로 미리 찍어내 메모리에 올려둔 뒤 SetActive(false) 상태로 꺼둡니다.

인게임 스폰 최적화: 실제 화면 멈춤이 절대 허용되지 않는 인게임 전투 중에는 몬스터를 새로 만들지 않습니다. 이미 만들어진 객체를 풀에서 꺼내 SetActive(true)만 호출하며, 단 1프레임 만에 가벼운 변수 초기화를 마칩니다.



3. 순환적 생명주기 관리 (Cyclic Lifecycle Management)
오브젝트 풀링의 적용을 받는 인게임 엔티티(Actor)들은 씬의 시작과 끝이 아닌, 풀을 오가는 독립적인 생명주기를 가집니다.

생명주기의 재정의: 인게임 Actor(캐릭터, 오브젝트 등)는 게임 도중 수시로 태어나고(OnSpawn), 죽어서 풀(Pool)로 돌아가는(OnDespawn) 순환적 생명주기(Cyclic Lifecycle)를 가집니다. 객체들의 진짜 생명주기는 오브젝트 풀에서 꺼내지고 들어가는 시점입니다.

안전한 비활성화: 객체가 죽어서 풀에 반환될 때는 메모리에서 파괴(Destroy)되지 않고 비활성화 처리됩니다.

초기화 주체: Actor의 OnSpawn() 초기화 로직은 Hub가 아닌 Object Pool Manager 또는 네트워크 스포너(FishNet)가 호출해야 합니다. 이 스폰 과정은 시스템 인프라 구축이 완료된 후, 본격적인 게임이 시작되고 나서야 비로소 실행됩니다.



4. 전역 및 씬 단위 격리 (Global & Scene Context Isolation)
게임의 규모와 메모리 정리 시점에 따라 풀 매니저의 유효 범위를 안전하게 나누어 사용할 수 있습니다.

독립적 운영: 메모리 관리를 위해 풀 매니저를 전역(GlobalPoolManager) 단위와 씬 전용(ScenedPoolManager) 단위로 쪼개어 배치할 수 있습니다.

물리적 가방 분리: 이들은 1계층 Context의 분리에 따라 완전히 다른 메모리 가방(Dictionary)에 저장됩니다. 전역 씬의 가방(ProjectContext.Inst.managerHub.moduleDict)에는 전역 풀 인스턴스가 들어가며, 게임 씬의 가방(SceneContext.Inst.managerHub.moduleDict)에는 씬 전용 풀 인스턴스가 들어갑니다. 따라서 동일한 클래스 타입(typeof(ObjectPoolManager))을 키(Key)로 사용하더라도 절대 서로 덮어쓰기 충돌이 일어나지 않습니다.



5. 상향식 자동 등록망 연동 (Event-Driven Automatic Registry)
수시로 꺼내지고 반환되는 객체들은 Hub와 물리적으로 결합하지 않고 통신망을 통해 자신의 상태를 알립니다.

생명주기 콜백 활용: 멀티플레이 게임이나 탄막 슈팅처럼 잦은 생성과 파괴가 일어나는 환경에서는 OnEnable과 OnDisable 콜백에 이벤트 등록/해제 로직을 넣어둡니다.

자동화된 전화번호부 갱신: 객체가 풀링 환경에서 켜지고 꺼질 때마다 상향식(Bottom-up)으로 허공에 이벤트를 던지므로, ActorHub(전화번호부)의 참조 목록이 완벽하고 자동으로 갱신됩니다
